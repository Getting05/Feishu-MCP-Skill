# 原生文档写作

在论文翻译、技术报告和长篇文档任务中，先理解源材料的结构，再选择飞书的实际块类型。`read_feishu_document` 返回的是文本摘要与块 ID；它不足以证明粗体、公式、图片或表格的完整结构。需要检查结构时，使用 `search_feishu_api` 查 Docx 的“获取所有块”或相应块接口，并查看官方文档中的请求与响应 schema。

## 选择表示方式

| 源内容 | 飞书目标 |
| --- | --- |
| 标题与层级 | Heading 块，保留层级和编号 |
| 有序/无序列表 | Ordered/Bullet 块 |
| 代码 | Code 块，保留语言和缩进 |
| 表格 | Table 块及单元格子块，保留行列、表头、单位、注释 |
| 引用 | Quote 块 |
| 链接 | 富文本链接元素 |
| 公式 | 官方 Docx schema 支持的 `equation` 元素或块 |
| 图片/图表 | 图片块与真实素材；图号和图注放在相邻内容中 |

`append_feishu_markdown` 经飞书 Markdown 转换，可创建标题、列表、表格、代码和富文本。先对复杂内容做小范围转换并读回；不要假设所有 Markdown 扩展都映射到期望的块。它单次最多接受 1000 个转换后的块，超限按章节追加。该工作流**拒绝图片**：图片需要官方媒体上传，再将素材绑定到 Image Block；若无法上传，应保留图注并明确说明图本身未插入。

## 公式

公式要保留上下标、希腊字母、点/帽符号、矩阵、分段条件及变换链。高层纯文本工具不会创建原生公式，例如下面应使用官方 Docx 富文本/块接口中支持的 equation 结构：

```latex
\hat{c}_{\mathrm{smooth}}(q,t)=q_t-q_{t-1}
```

不要把它改写成 `ĉ_smooth(q,t)=q_t−q_{t−1}` 后当作已经完成公式排版。若目标 API 的确切 equation schema 未知，先查 `search_feishu_api` 给出的官方文档或读取同类型已有块；不要猜测字段。写入后用原始块接口检查返回的是 equation，而不只是 `text_run` 字符串。

## 编辑与翻译

- 编辑原文前，读取并找到目标块。局部粗体、链接或公式要保留时，使用 Docx 块接口定点更新；`update_feishu_text_block` 会替换整块内联内容。
- 来源是论文/PDF 时，段落、图表、数字、单位、引用和术语都以原文为准。不能把全文翻译压缩成摘要，也不应悄悄修正原文中相互矛盾的数据；必要时标注矛盾。
- 图片与表格常在 PDF 文本提取中丢失。源材料可视化时先核对相关页；无法插入的图示要说明缺失，不要用一句文字描述冒充原图。
- 大文档按章节写入和核对：标题顺序、公式类型、真实表格、代码、图注、链接和旧内容是否重复。只有相关结构都正确时才报告完成。
